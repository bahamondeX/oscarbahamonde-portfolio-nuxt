# Browser verification

Run `npm ci`, `npx playwright install chromium`, then `npm run test:e2e`. The suite starts a local Nuxt server at port 3187, or uses `E2E_BASE_URL` when provided. `CHROME_PATH` can select an installed Chromium executable; each run creates a fresh isolated browser context. It never connects to an existing browser or profile.

The desktop (1440×1000) and mobile (390×844) projects verify both locales and themes, all nine dock destinations, metadata, horizontal overflow, language changes without document reload, persisted theme, keyboard booking with an intercepted S/20 checkout conflict, and the separate accessible assistant panel with an editable draft before consent. Booking requests are intercepted; no payment, event, email or model invocation occurs. Medium pagination checks every reported page, with at least the ten entries in the verified snapshot. Screenshots, JSON results, traces on failure and the HTML report are written to ignored `reports/`.

Logo tests compare actual screenshot pixels after CSS/theme rendering. Transparent PNGs are measured against a second screenshot of their real chip with the image hidden. For opaque rectangles, a uniform intrinsic corner background is detected and used instead; background pixels never count as the logo. One-pixel erosion removes anti-aliasing edges. The 10th percentile of remaining solid foreground must be ≥3:1, meaning at least 90% meets the target. Every logo produces a screenshot and JSON measurements. `scripts/analyze-logos.mjs` classifies source luminance and chooses a chip; that source analysis is not a substitute for this rendered test.

`npm run audit -- https://oscarbahamonde.com/es` runs Lighthouse in a separate headless browser. The 2026-11-14 managed macOS attempt failed before navigation: Chromium's crashpad Mach bootstrap returned Permission denied (1100) and aborted. This is an environment launch failure, not a Lighthouse result. No numeric Lighthouse or rendered E2E success is claimed until the reports are produced in a compatible runtime.

## Reproducible Ubuntu run (2026-11-14)

The new task explicitly requests a browser CI job. `.github/workflows/playwright.yml` runs on Ubuntu on main pushes, pull requests and manual dispatch. It installs the lockfile's Chromium, builds Nuxt and starts an isolated local production build; no production secrets, email, calendar event or payment are used. The 24 cases include all eight locale/theme/viewport logo combinations. Artifacts preserve successes and failures for 30 days. This demonstrates the committed build; it is not a claim of a real payment, microphone device or production conversation.

The local official installation was repeated into `/tmp/oscar-playwright-browsers` because the preinstalled Chromium1181 did not match Playwright1.65.1 (required1255). Chromium159 full headless launch with `--no-sandbox`, `--disable-crashpad` and `--disable-crash-reporter` still aborted before a page. Docker could not connect to the managed host socket (`operation not permitted`). No permissions or host protections were bypassed. Evidence is in `docs/audit/after/playwright-environment/`.

Each logo is captured with `locator.screenshot({scale:'css'})`, including a matching opacity-zero background capture. No viewport-coordinate clipping is used. `scripts/logo-report.mjs` combines the eight variant reports into `docs/audit/after/logo-contrast-rendered.json`; missing variants explicitly fail as `incomplete`. The foreground statistic is the 10th percentile after one-pixel erosion, with minimum and fraction above3:1 retained for inspection. Thus the pass criterion means90% of recognizable solid foreground meets3:1; it is not a statement that every antialiased pixel has3:1 contrast.
